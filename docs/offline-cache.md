# 自动离线缓存

现有首页、问题、回答、文章和评论页面共用在线请求与本地缓存。联网时优先请求真实接口；明确断网或读取请求发生连接故障时，自动回放持久化数据，不需要切换页面或进入专门的离线入口。

## 使用与配置

在「设置 → 系统与更新 → 自动离线缓存」调整数量、下载网络和容量，也可以搜索「离线」「缓存」。

| 配置 | 默认值 |
| --- | --- |
| 自动准备内容 | 开启 |
| 自动下载网络 | 仅非计费网络（通常为 Wi-Fi） |
| 问题数 | 100 |
| 每题回答数 | 50 |
| 文章数 | 50 |
| 每个问题、回答、文章的一级评论数 | 20 |
| 每个评论区额外回复总数 | 10 |
| 内容及图片容量 | 2048 MB |
| 已读保留时间 | 24 小时 |

数量是后台准备目标，不限制联网浏览。接口没有足够内容、容量不足或后台受限时，实际数量可能少于目标。正常浏览得到的数据也会保存；关闭自动准备后，已有内容继续可用。视频流和视频文件不预下载，封面图片可以缓存。

首次使用需要先联网准备。设置页显示已准备的内容数、图片数、待补图片和待处理任务。立即补充仍遵守下载网络和容量设置。清空缓存需要确认，不影响账号、收藏及原有浏览历史。

## 数据链路

- Ktor 的 `OfflineContentPlugin` 在内容读取请求解码前保存成功响应，覆盖 Web 与移动端客户端；登录、身份验证、写操作和遥测接口不在缓存白名单内。
- 缓存按账号隔离，Web 与移动端接口分别识别。键包含协议、主机、路径、有效请求参数、排序、分页、include 字段和缓存版本。额外 include 字段允许满足较窄的同类请求，不会用缺字段的数据冒充完整详情。
- 明确断网且命中缓存时直接返回；弱网时，有缓存的前台请求最多尝试约 3 秒后回退。401、403 等权限响应不会伪装成离线成功，404/410 会撤销对应详情的可用标记。取消请求正常传播。
- 接口数据、内容关系、任务和进度放在独立 SQLite 数据库中；图片放在同账号的资源目录。目录位于应用的 `noBackupFilesDir/offline/`，不迁移原有业务数据库，也不进入系统备份。
- 列表和正文图片分别通过 Coil 拦截器、WebView 资源拦截读取同一份本地文件。图片共享引用，最后一个引用解除后才回收。

## 离线首页与分页

离线首页从已经保存完整详情的内容生成原接口格式的响应，Web 和移动端各自使用现有解析器。每个问题优先呈现一个未读回答，问题内其余回答仍从原问题页与回答导航访问。读完后，后续首页请求可以呈现同题的其他未读回答。

这样可避免在线推荐变化后，首页全部指向尚未准备的新内容，而已缓存的问题失去入口。首页分页使用固定的本地内容快照；内部游标只用于本地，恢复联网后会移除这些参数再请求真实接口。

回答、评论等列表保留服务器原始游标，并记录缓存分页版本。新首页/列表首屏不会直接拼接旧版本后续页；离线缓存到头后结束本次加载，恢复联网后允许继续请求，不能把本地边界永久当成服务器末尾。尚未缓存完整详情的内容不会显示成可离线打开的卡片。

## 后台准备与维护

候选来源沿用推荐模式，Web、Android、混合模式分别抓取对应推荐。移动端卡片从导航地址识别内容，不模拟用户点击。根据候选问题补充问题详情、回答列表、回答正文，再补文章、评论、回复与图片。

任务和重试时间持久化。优先扩大问题覆盖面，并让每个问题先有正文可读，再补足剩余回答和评论。请求失败退避重试，单个图片失败不会阻挡后续图片。前台恢复、网络恢复以及约每小时的 WorkManager 任务都可触发准备；每轮有时间预算，剩余任务留待下一轮，不承诺应用被系统强制停止后继续运行。

预取只读取数据，不调用页面加载流程，不上报阅读或触发点赞、收藏、发布等操作。阅读进度单独保存；正文加载后阅读至少约 15 秒、到达末尾约 95% 才计为已读。打开过或预取成功不等于读完。

联网维护时优先保留未读内容，清理达到保留时间的已读正文、附属评论及无引用图片，同步移除本地列表中的失效入口。近期正在阅读的内容延迟回收，已读标记保留约 30 天用于去重。容量不足时停止新增，不靠自动删除未读内容腾空间。账号切换停止旧账号准备，删除账号会清理其缓存分区。

## 范围与验证

未缓存的排序、后续分页、陌生搜索结果和其他未接入接口仍需要联网；点赞、发布评论等写操作不支持离线排队补发。单份接口响应超过约 1.5 MB、单张图片超过 15 MB 时不进入自动缓存，在线阅读不受此缓存限制。

自动化测试覆盖 HTTP 响应回放、弱网故障回退、权限/错误响应、取消传播、Web/移动端解析兼容、本地分页、数据库关闭重开、账号隔离、数量上限、任务续跑、已读清理、共享图片和容量约束。

```sh
./gradlew :app:testLiteDebugUnitTest :app:assembleLiteDebug --no-configuration-cache
```

2026-11-18 已通过 34 项本机单元测试，以及 Neo 3 Ultra（Android 14 / API 34）上的五项实机数据链路测试：

1. 联网阶段写入问题、回答、评论和图片，保存阅读位置。
2. 关闭无线网络并重启应用进程后，从 SQLite 和文件缓存回放，网络引擎调用次数为 0。
3. 恢复联网后返回新正文并更新缓存，阅读位置保留。
4. 不打开页面，自动准备配置的 1 个问题、2 个回答、1 篇文章及评论/回复，任务队列归零。
5. 再次断网，用真实 Android HTTP 客户端读取自动准备的回答、问题回答列表、评论以及 Web/移动端首页。

实机验证同时发现并修复 VPN 断网后仍保留 VALIDATED 标记的问题：网络判断会核实底层承载网络。测试结束已恢复设备网络并移除独立测试包，原有 0.1.7 应用及其数据保留。

实机测试源位于 `app/src/offlineDeviceTest/java/`。使用以下参数构建独立测试包，避免覆盖正常安装：

```sh
./gradlew :app:assembleLiteDebug :app:assembleLiteDebugAndroidTest \
  -Papp.offlineDeviceTests=true -Papp.debugApplicationIdSuffix=.offlinecheck \
  --no-configuration-cache
```

联网预取测试使用固定接口响应；没有使用真实知乎账号验证在线预取。按项目约定未进行截图或本地视觉复核。
